# WeKnora 私有部署实战：从裸机到微信问答 0.7 秒响应

## 为什么要私有部署

市面上的 AI 问答工具很多，但把企业内部文档交给第三方托管，很多老板第一反应是摇头。私有部署的价值就在这里：

- **数据不出门**：文档、向量库、对话记录全部留在自己的服务器上
- **成本可控**：接国产模型 API，按量计费，没有按人头的大额订阅费
- **渠道自由**：网页、API、微信，想让团队在哪用就在哪用

我基于 WeKnora 给自己和客户各搭了一套，把完整链路记录下来。

## 整体架构

```
微信 / 浏览器
     │
     ▼
阿里云反代（Nginx + SSL）          ← 公网入口，域名与证书在这层
     │
     │ frp 隧道
     ▼
家宽服务器（Docker）               ← 数据与算力在这层
 ├─ WeKnora 全套容器（Web/后端/向量库）
 ├─ new-api 模型网关
 └─ frpc
```

公网入口和数据落地分离，是这套架构的核心：域名和证书放在云上反代，真实数据压在家里的机器上。

## 部署步骤

### 1. 基础环境

WeKnora 官方提供 Docker Compose 编排，一条命令拉起全家桶：

```bash
git clone <weknora-repo>
cd weknora
docker compose up -d
```

### 2. 接入模型

我没有让 WeKnora 直连模型 API，而是中间加了一层 **new-api 网关**：

- 统一管理多个国产模型渠道，故障时可以切换
- 额度、令牌、调用量一目了然
- WeKnora 只需要配一个 OpenAI 兼容地址

### 3. 知识库调优

这一步决定回答质量，比部署本身更花时间：

- **切分策略**：按文档标题层级切，而不是无脑 512 token，段落语义完整得多
- **混合检索**：向量 + 关键词双路召回，专有名词的命中率明显提升
- **Prompt 约束**：要求模型只基于检索内容回答，命中不了就说不知道

### 4. 内网穿透与 HTTPS

家宽服务器没有公网 IP，用 frp 打隧道到云上反代：

```ini
# frpc.ini（家宽侧）
[weknora]
type = tcp
local_ip = 127.0.0.1
local_port = 8080
remote_port = 18080
```

云上 Nginx 终结 TLS，反代到 frp 端口。证书用 acme 自动续期，整条链路对用户是标准 HTTPS。

### 5. 微信问答渠道

把知识库后端封装成 webhook，接到微信消息通道上。团队在微信里直接提问，实测首字响应 **0.7 秒**，回答会附上引用来源。

## 踩坑记录

1. **大文档切分后检索变差** —— 根因是切分丢了标题上下文，改用层级感知切分解决
2. **frp 隧道偶发断连** —— 家宽重拨后 IP 变化，frpc 心跳 + 自动重连即可，但要给反代配好超时，避免上游挂着半个死连接
3. **模型输出不稳定地跑题** —— 检索命中率没问题，是 Prompt 里没有强制"仅基于资料回答"，加上硬约束后明显收敛
4. **8G 内存机器吃紧** —— 向量库和模型网关分开部署，限制各容器内存配额后稳定
